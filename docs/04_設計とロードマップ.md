# 🏗️ 設計とロードマップ

## 基本方針

### ルールとUIを完全に分ける

```
┌──────────────────────────────────────────┐
│  engine/     ゲームのルール（純粋なPython）    │
│              画面のことを一切知らない           │
└──────────────────────────────────────────┘
              ↑ 同じAPIを叩くだけ
      ┌───────┴────────┬─────────────────┐
      │                │                 │
┌───────────┐  ┌──────────────┐  ┌──────────────┐
│ server/   │  │ simulate.py  │  │ （将来）      │
│ Web対戦    │  │ 自動対戦テスト │  │ スマホ / 他UI  │
└───────────┘  └──────────────┘  └──────────────┘
```

この分離があるおかげで：

- 🖥️ UIを作り直しても、ルールのコードは1行も変わらない
- 🤖 CPU同士を何千回も対戦させてバランスを検証できる（画面を描画する必要がない）
- 🌐 LAN対戦にするとき、`engine/` は触らなくていい

### 数値はコードに書かない

バランスに関わる数字はすべて [`balance.json`](../balance.json) にある。
調整するときにPythonを読む必要がないので、プログラマ以外でも触れる。

## 🔌 サーバーAPI

ブラウザとサーバーはこの4つだけでやり取りしている。

| メソッド | パス | 内容 |
|---|---|---|
| `GET` | `/` | 画面（index.html）を返す |
| `GET` | `/api/state` | 現在の盤面を返す |
| `POST` | `/api/new` | 新しいゲームを始める |
| `POST` | `/api/action` | 行動を送る。CPUの番も自動で進めて結果を返す |

### 送る行動の形

```json
{ "action": { "type": "attack" } }
{ "action": { "type": "swap",  "bench": 0 } }
{ "action": { "type": "item",  "hand": 2 } }
{ "action": { "type": "end_turn" } }
```

### 返ってくる盤面の形

```json
{
  "turn": 5,
  "is_my_turn": true,
  "me":       { "trainer_hp": 170, "battle": {...}, "bench": [...], "hand": [...] },
  "opponent": { "trainer_hp": 140, "battle": {...}, "bench": [...], "hand_count": 3 },
  "actions":  [ { "type": "attack", "label": "⚔️ 攻撃 → ♠K 暴君" }, ... ],
  "log":      [ "..." ],
  "winner":   null
}
```

> 💡 **重要**：`opponent` には `hand`（手札の中身）が入らない。`hand_count`（枚数）だけ。
> 相手の手札を隠す処理は **サーバー側** でやっている（`Game.view(viewer)`）。
> ブラウザ側で隠しているわけではないので、通信を覗かれてもカンニングできない。

### ブラウザ側はルールを知らない

「いま何ができるか」は、サーバーが `actions` 配列で教えてくれる。
ブラウザはそれをボタンやクリック可能なカードに変換しているだけ。

→ **ルールを変更してもブラウザ側のコードを直す必要がない。**

## 🛠️ よくある改造のやり方

### 数値バランスを変えたい

1. `balance.json` を編集する
2. `py -3 simulate.py --games 400` で影響を確認
3. カードリストの表記を更新 → `py -3 tools\gen_cardlist.py`

### カードの能力を変えたい／増やしたい

1. `engine/cards.py` の `FACE_ABILITIES`（モンスター）または `ITEM_FACE`（アイテム）に定義を書く
2. `engine/game.py` に処理を追加する
   - モンスターの技 → `_on_enter` / `_do_attack` / `_begin_turn` のどれかに分岐を足す
   - アイテム → `_use_item` に `elif t == "新しい効果名":` を足す
   - 使用条件の判定 → `_item_usable`
3. 数値は `balance.json` の `ability_values` / `item_values` に置く
4. `py -3 tools\gen_cardlist.py` でドキュメントを更新

### CPUを強く（弱く）したい

`engine/ai.py` の `_score_item()` と `choose_action()` だけを触る。
ここは `Game` から独立しているので、丸ごと差し替えても他に影響しない。

## 🚀 ロードマップ

### ✅ ステップ1：PoC（完了）

- [x] ゲームエンジン（ルール一式）
- [x] CPU対戦相手
- [x] ブラウザで動く画面（マウス操作）
- [x] バランス検証用の自動対戦

### 🔜 ステップ2：LAN対戦

**ゴール**：同一LAN内の2台のPCから接続して、人間同士で対戦する。

やること：

1. **部屋（room）の概念を追加**
   - いまは `STATE["game"]` にゲームが1つだけ。これを `{room_id: Game}` の辞書にする
   - 「部屋を作る」「部屋に入る」画面を追加
2. **プレイヤーの識別**
   - ブラウザごとにトークンを発行し、`viewer` 番号（0 or 1）と紐づける
   - `view(viewer)` は既にプレイヤー視点で盤面を返せるので、ここは修正不要
3. **相手の操作をリアルタイムに反映**
   - まずは **1〜2秒ごとのポーリング**で十分（ターン制なので即時性はそこまで要らない）
   - 必要なら後から WebSocket に置き換える
4. **起動**
   - サーバー役のPCで `py -3 run.py --lan`
   - 他のPCから `http://<サーバーPCのIP>:5000/` にアクセス
   - ⚠️ 初回はWindowsファイアウォールの許可が必要
   - ⚠️ `https` ではなく `http`。LAN内なら証明書は不要（むしろ用意が面倒）

**現時点でLAN対戦の準備ができている部分：**

- ✅ 相手の手札を隠す仕組み（サーバー側で実装済み）
- ✅ `--lan` フラグでの外部公開
- ✅ ルールがUIから独立しているので、通信方式を変えてもエンジンは無傷

### 💭 ステップ3以降（アイデア）

- 見た目の強化（カード画像、攻撃アニメーション、効果音）
- 対戦リプレイの保存・再生（ログは既に全部残っている）
- CPUの強さ選択（弱い／普通／強い）
- デッキ構築（52枚固定ではなく、使うカードを選ぶ）
- リアルのトランプで遊ぶ用の「印刷できるカード一覧」出力

## ⚠️ 技術的な注意点

| 項目 | 内容 |
|---|---|
| Python | 3.9 以上。`py -3` で起動する（`python` はWindowsストアのダミーに繋がるので使わない） |
| 依存ライブラリ | **Flask のみ**。すでにインストール済みなので追加作業は不要 |
| 文字コード | ソース・JSON・md はすべて **UTF-8**。Windowsのメモ帳で保存すると壊れることがあるので注意 |
| Google Drive | プロジェクトが同期フォルダ上にあるため、**2台で同時に編集しない**こと |
